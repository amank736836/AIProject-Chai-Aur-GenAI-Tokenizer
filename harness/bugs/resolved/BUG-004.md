# BUG-004 — Theme Storage Failure Could Prevent the Page from Initializing

- **Bug ID:** BUG-004
- **Title:** Theme preference access crashed under blocked localStorage
- **Severity:** Moderate availability/accessibility edge case
- **Priority:** P2
- **Feature:** FEAT-005 — theme preferences
- **Environment:** Chromium 153, local production build; storage getter deliberately throws `SecurityError`; reproduced 2026-10-11.
- **Preconditions:** Browser profile/security policy denies access to `window.localStorage`.

## Steps to reproduce

1. Before navigation, override the `window.localStorage` getter to throw a `SecurityError`.
2. Open `/` and wait for the page to hydrate.
3. Observe the theme initialization and attempt to use the theme toggle.

## Expected

The page stays usable, chooses the OS color-scheme fallback, and applies theme changes for the current session even if persistence is unavailable.

## Actual before fix

The `ThemeToggle` effect directly read `localStorage` without handling a `SecurityError`. In Chromium the main `.status-pill` never appeared within the 8-second assertion window; the app had failed to initialize normally.

**Reproducible:** YES with a browser storage-denial injection.<br>
**Evidence:** the initial regression test failure was captured in `.playwright-results`; fixed behavior is asserted by the “theme control degrades gracefully when localStorage is blocked” test in RUN-2026-002.

## Root cause

Theme initialization and toggle writes accessed localStorage outside a try/catch, even though the shared storage hook and prepaint bootstrap already tolerate unavailable storage.

## Fix

Catch storage read/write exceptions in `ThemeToggle`. Accept only stored `light`/`dark` values; otherwise fall back to `prefers-color-scheme`. Apply in-memory theme state and `data-theme` even when persistence writes fail.

## Regression test

`npm run test:e2e` → blocked-storage test passed in Chromium: route hydration/status succeeded, theme toggle changed to light under a dark OS preference, and no page error was recorded. Targeted verification also passed before the full-suite run.

- **Status:** RESOLVED — verified in rendered Chromium behavior.
