# BUG-003 — Tilted Training Panel Could Miss Pointer Clicks on Speed Controls

- **Bug ID:** BUG-003
- **Title:** Parent tilt moved the speed button out from under the pointer
- **Severity:** Moderate user-visible interaction failure
- **Priority:** P2
- **Feature:** FEAT-001 / FEAT-005 — training controls and interactive presentation
- **Environment:** Chromium 153, local production build; reproduced at 1366×900 on 2026-10-11.
- **Preconditions:** Training section visible; automatic training stopped; speed 1× selected.

## Steps to reproduce

1. Scroll to the Train section at 1366×900.
2. Move the mouse pointer onto the `2×` speed button and click it.
3. Inspect the selected button's `aria-pressed` state and `localStorage['tokenizer-speed']`.

## Expected

The selected speed changes to 2×, `aria-pressed` becomes `true`, and the stored interval changes from 80 ms to 38 ms.

## Actual before fix

A real Playwright pointer click left `aria-pressed="false"` and `tokenizer-speed` at `80`. A capture-phase event listener showed the pointer event landing on the `.speed-control` parent rather than the button after the ancestor card rotated. Calling `HTMLElement.click()` updated the state, isolating the fault to pointer hit-testing rather than the React handler.

**Reproducible:** YES with pointer automation.<br>
**Evidence:** browser diagnostic in RUN-2026-002 session; regression assertions are in the training-controls and native-touch E2E tests.

## Root cause

`TiltCard` rotates its whole card on pointer movement, which can shift small interactive descendants between pointer movement and activation.

## Fix

When a pointer event originates inside a button, link, input, select, or other interactive target, `TiltCard` immediately resets its tilt and applies `is-interacting` with transitions disabled. Pointer tilt remains enabled on non-interactive card areas.

## Regression test

- `npm run test:e2e` → training-controls test clicks 2× with a mouse, checks `aria-pressed`, verifies persisted speed after reload, and passes.
- Native touch test taps 2× in an `isMobile`/`hasTouch` Chromium context and passes.

- **Status:** RESOLVED — mouse and touch interactions verified in rendered Chromium.
