# BUG-002 — Round-Trip Indicator Could Call Normalized Output Lossless

- **Bug ID:** BUG-002
- **Title:** Round-trip indicator overstated whitespace-normalized output
- **Severity:** Low
- **Priority:** P2
- **Feature:** FEAT-002 — BPE encode/decode
- **Environment:** Chromium 153, local production build; verified 2026-10-11 at 390×844.
- **Preconditions:** BPE initialized; open Encode section.

## Steps to reproduce

1. Enter `  chai  ` including leading and trailing spaces.
2. Compare the input with the decoded output and inspect the round-trip pill.

## Expected

The UI should distinguish exact string equality from canonical whitespace normalization.

## Actual before fix

`BPETokenizer.decode()` trims outer whitespace while `roundTripOk` compared `decoded.trim().toLowerCase()` with `input.trim().toLowerCase()`. For `  chai  `, the page could therefore label decoded `chai` as a lossless round trip.

**Reproducible:** YES by source logic; the fixed rendered behavior is covered by the browser test.<br>
**Evidence:** `src/app/page.tsx` (`roundTripOk`); [`RUN-2026-002` encode edge-case test](../../automation/e2e/playground.spec.mjs); [`encode-edge-cases.json`](../../evidence/logs/RUN-2026-002-encode-edge-cases.json).

## Root cause

A normalized, case-insensitive comparison was described as lossless despite the decoder's intentional whitespace canonicalization.

## Fix

Changed the UI comparison to exact string equality (`decoded === input`). The browser test enters `  chai  ` and observes `round trip differs` with decoded text `chai`; it also verifies exact-case-preserving text reports `lossless round trip`.

## Regression test

`npm run test:e2e` → Chromium test “encode/decode, exact round-trip messaging, keyboard shortcuts, copy, and long Unicode input work” PASS, RUN-2026-002.

- **Status:** RESOLVED — verified in rendered Chromium behavior.
