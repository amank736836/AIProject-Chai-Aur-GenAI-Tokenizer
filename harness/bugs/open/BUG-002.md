# BUG-002 — Round-Trip Indicator Can Call Normalized Output Lossless

- **Bug ID:** BUG-002
- **Title:** Round-trip indicator can call normalized output lossless
- **Severity:** Low
- **Priority:** P2
- **Feature:** FEAT-002 — BPE encode/decode
- **Environment:** Static source review of the current checkout; browser not run.
- **Preconditions:** BPE initialized and encode section open.

## Steps to reproduce

1. Enter text with leading/trailing whitespace, for example `  chai  `.
2. Compare the input with decoded text.
3. Observe the round-trip pill.

## Expected

The UI should either compare exact strings and report a difference, or explicitly label the result as equal after canonical whitespace normalization.

## Actual

`BPETokenizer.decode()` trims trailing whitespace and `page.tsx` computes `roundTripOk` by comparing `decoded.trim().toLowerCase()` with `input.trim().toLowerCase()`. Leading/trailing whitespace is ignored, so the page can say “lossless round trip” even though exact input formatting was not preserved. BPE's whitespace normalization is tested by TC-006; the UI reproduction TC-108 remains NOT_RUN.

**Reproducible:** YES by source logic; the visual behavior is not browser-verified.  
**Evidence:** `src/lib/bpe.ts` (`decode`), `src/app/page.tsx` (`roundTripOk`); [`TC-006`](../../test-cases/bpe-tokenizer/edge-cases.md), [`TC-108`](../../test-cases/ui-playground/negative.md).

## Root cause

The UI labels a case-insensitive, trimmed comparison as lossless, while tokenizer decode canonicalizes whitespace.

## Fix

**Not applied.** Clarify product semantics and adjust UI indicator/comparison in a separate application-code change.

## Regression test

TC-108 manual browser scenario; ideally add a page-level test after a DOM/browser test tool is approved.
